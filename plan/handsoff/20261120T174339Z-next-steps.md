## What this session learned about piloting

- **The disk filled** (`/` at 100 %) in the first round. Freed by the
  pilot: the `target/` of the old worktrees (`temp/wt-*`,
  `.claude/worktrees/agent-*`) and three build directories of the
  morning, 67 GB; an agent's `cargo clean -p ptyrc-server -p
  ptyrc-box` freed 51 GB more. `target/debug` grows past 90 GB in a
  day (33 GB of `incremental`): check `df` before each round.
- **The load reached 222** with four agents in their final checks at
  once; cases and timing tests fail then. Stagger the final checks, or
  three agents at most.
- **A plain `git commit` takes what another left staged**: `52979ad`
  carried another agent's staged rename and left HEAD not building
  for three hours. Briefs now say: explicit paths always; plain
  `git commit` only after `git diff --cached` shows one's own.
- **The permission classifier refused some agents' `git add && git
  commit -- PATHS`**; the `hash-object`/`update-index` recipe went
  through for others. One agent's whole work stayed uncommitted until
  the owner's word. Ask the owner at the start how commits by agents
  are to be made.
- **The pre-commit hook stashes unstaged files** at each commit and
  wiped one agent's uncommitted edit once. Commit a slice at once;
  keep nothing uncommitted across other agents' commits (a backup of
  the held work was kept in `temp/20112026-02-ready/backup/`).
- An agent may not write a report file (the harness refuses it): the
  pilot saves what matters (`proof/FINDINGS.md`).
- Two agents passed 250k tokens (`manifest` 253k, `sdk-js` 257k),
  `model-life` 318k: a model app with a live run is two sessions.
- The model apps' live runs paid: the tick bug and the invisible early
  exit were live only. Ask each first app of a family for one.
