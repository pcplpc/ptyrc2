## Topic 1: layers (owner's request, core)

"A sandwich" with transparency. The app's text is in front of our
drawings by default; multi-layer scenes are easy: static background,
animations in front, the app's text in front again, and so on.

Today a sprite has `blend` (`over`, `behind`, `tint`) and `z`; the default
blend is `over`. To design and build:

- The app text as one layer in an order of named or numbered layers;
  layers below it are seen only through blank app cells, layers above
  cover it.
- `behind` as the default (changes `design.md`, the pilot, the CLI, the
  tests).
- What "blank" means for a background layer: a space with default
  background only, or any space; a cell whose app background is set.
- Background colour of a sprite behind text: the app glyph keeps its
  foreground and takes the sprite's background (true sandwich), per cell.
- Optional per-cell alpha on RGB hosts.
- Code: `rust/ptyrc-core/src/scene/` (`raster.rs`, `spec.rs`, `mod.rs`).

## Topic 2: core polish

From the reports of the first session, by priority:

1. Preset cost: the three presets run on every `Frames::update`, about
   250 µs of the 610 µs key echo (`ptyrc run --no-presets` to compare).
   Cache detection per pane; re-run on layout change or on a throttle.
2. `frames.update` costs 250-400 µs when every row changed.
3. Islands of an extended frame are never collected; each shell `clear`
   allocates one at +100000 rows, and `frame.text` without a range then
   fails. Default the range to the current island; collect old islands.
4. A pager page-down with no overlapping row lands on an island until a
   later scroll overlaps. `less` and `more` must work without a preset:
   look at what distinguishes a page-down from a jump.
5. `FrameEvent::Shift` is also emitted when an island is translated onto
   the current one; check `Scene::shift` moves sprites in that case.
6. The scene still uses its own width table: switch to
   `ptyrc_vt::char_width` / `str_width`.
7. A finite animation added while the raw frame is not yet usable (250 ms
   after the first screen) plays unseen.
8. Update in place a sprite made by a draw extension.
9. Engine with sprites under a flood feeds both models (14 MiB/s).
10. Untested: splice away from the cursor, identity across a width change,
    layout flaps under load, a host reporting 0x0, one `write` per burst
    at the syscall level, underline colour and hyperlinks in the checker.
11. Known and accepted: main-screen reflow on host resize; a burst ending
    inside an escape sequence while it scrolls; the cursor is not hidden
    during repair on hosts without mode 2026.

Real TUIs to try, the owner's list: htop, less, man, tmux, ranger,
glances, opencode. Only a stand-in agent TUI was tried, not a real one.
Add each to `scripts/e2e-frames.sh` when installed.

## Topic 3: client apps (owner's request, after the core)

`plugins/client-apps/python/`, package `ptyrc-apps`. Smooth, elegant,
fast, responsive; written as examples people learn from. `confetti.py`
and `clock.py` and the package README are the model.

- **confetti**: `--spawn --rate <rate>`: `<rate>` bursts per minute;
  `--spawn` alone is 20 per minute, one every 3 s.
- **fishtank**: fishes `<*//><` afraid of the cursor (`screen.cursor` with
  `trail`). It lives inside a scrollable frame: fishes hold frame
  coordinates of an extended frame and scroll with the content, not with
  the window.
- **snake**: plays alone, eats apples, goes around the words of a long
  scrolling buffer (vim, less).
- **sand**: fills an idle pane (tmux), piles on the text.
- **flower**: drawn next to the word "flower", anchored to the text.
- **clock**: exists; revisit with layers.
- A showcase of sprite handling and scrollable frames on vim, less, more.
- A demo of the dynamic frames: tmux panes and windows, vim splits, each
  pane with its own drawing, frames found again when a window comes back.
  `scripts/demo-*.sh` in a detached or attached tmux.
- JavaScript client apps: later, out of scope.
